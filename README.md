# beta-reader-panel

A [Claude Code](https://claude.com/claude-code) Skill that reviews a manuscript chapter by
chapter, in one of two modes:

- **Analyst mode (default)** — one continuously-updated read: what kind of story this is, a
  detailed chapter summary, an honest read on writing quality + a rating, who's involved and how
  relationships stand, plus an optional off-structure sidebar. Written with a real voice — witty,
  genuinely engaged, and deliberately **not sycophantic** — no empty cheerleading, no softened
  criticism. Runs directly in the main conversation; no subagent.
- **Panel mode** — 2-3 distinct beta readers, randomly picked from an 11-persona roster spanning
  teens, young adults, adults, middle-aged, older, genre-superfan, casual, and craft-critic
  readers, each reacting to the manuscript with their own **isolated** memory so none of them
  anchor on each other's opinions.

Both are reader-side *reactions/analysis, not editing* — no line edits, no prose fixes. For that,
see the companion skill,
[manuscript-editor](https://github.com/SwaroopShenoy/manuscript-editor-skill).

## Why two modes

Most "review my chapter" requests just want a record of what happened and an honest quality
read — that's analyst mode, and it's the default. It doesn't need subagent isolation because
there's only one voice giving one read; running it straight in the main conversation means every
chapter carries no fixed spawn cost and can see the *whole* book's history (manuscripts here run
~30 chapters, comfortably small enough to keep in full) instead of a trimmed window.

Panel mode exists for the different, explicit ask — "what would readers think" — where isolation
actually matters. Real authors run parallel beta readers because one reader's reaction can
quietly bias how you read the next one's. Simulating that only works if the simulation respects
the same isolation, which turns out to require more than "write persona A, then persona B
without looking back": both generated in the same context window still means A's tokens are
sitting there influencing B's generation. So each persona's reaction is generated by its own
**subagent**, spawned in parallel, with a self-contained prompt that never mentions the other
personas exist — and each persona keeps its own private `living_reference.md` as the durable
record.

In both modes, the mechanical parts — assembling context, parsing a reply back into the tracking
file — are plain Python, not tokens. The remaining LLM step only *needs* to be a single
text-in/text-out call (feed it a bundle, get back a fixed set of `KEY: value` lines) — no tool
access required by the task itself.

## What's in this repo

- **`SKILL.md`** — the full workflow for both modes: cold start, mode selection, the analyst
  loop, the panel isolation loop, and output formatting for each.
- **Analyst mode toolkit:**
  - `toolkit/init_analyst.py` — scaffolds `_story_analysis/living_reference.md` for a manuscript
    (idempotent).
  - `toolkit/analyst_reference_template.md` — the reference file template.
  - `toolkit/build_analyst_prompt.py` — assembles the chapter + full prior history + the
    analyst's voice/format instructions into one prompt (defaults to the whole book's history,
    since these manuscripts run ~30 chapters — override with `--history N` for outliers).
  - `toolkit/record_analysis.py` — parses the seven-field reply (`OPENER`, `STORY_TYPE`,
    `SUMMARY`, `QUALITY`, `RATING`, `CHARACTERS`, optional `SIDEBAR`) into the chapter log, and
    rebuilds "Running notes" mechanically each time — scanning every prior chapter's character
    list and rating so the roster stays genuinely cumulative (a character absent from this
    chapter isn't dropped) without resending full paragraphs into every future prompt.
- **Panel mode toolkit:**
  - `toolkit/select_panel.py` — randomly picks 2 or 3 personas for a manuscript (idempotent —
    won't re-roll an existing panel) and scaffolds each one's living-reference file. `--list`
    prints the whole roster without touching any manuscript; `--personas slug1,slug2[,slug3]`
    picks specific readers instead of random ones.
  - `toolkit/personas/*.md` — eleven reader persona cards (`teen_male`, `teen_female`, `ya`,
    `adult_late20s30s`, `late20s30s_male`, `middle_aged`, `middle_aged_female`, `older`,
    `super_fan`, `casual_reluctant`, `craft_critic`) — each with a distinct voice, taste profile,
    and a `preferred_model` field (lighter models for lighter tasks, e.g. `opus` for the
    craft-focused critic, `haiku` for the teens).
  - `toolkit/living_reference_template.md` — the per-persona chapter-log template.
  - `toolkit/build_persona_prompt.py` — assembles one persona's card + trimmed reading history
    (default `--history 8`, since a subagent's fixed spawn cost makes a small window worth it) +
    the new chapter into a prompt bundle. Also writes the chapter's canonical label
    (deterministically parsed from its own heading — zero LLM cost) to a `.label` sidecar, so the
    same chapter is never logged under slightly different labels by different personas or
    sessions. Accepts `--chapter-file` to reuse a chapter already fetched once for the whole
    panel, and `--continuing` to build a lean bundle for a persona subagent that's already alive.
  - `toolkit/record_reaction.py` — parses a persona's `KEY: value` reaction back into their
    `living_reference.md`. Flags an entry visibly (`⚠`, in the file itself) if 4+ of the 10
    fields came back empty — a sign the subagent didn't follow the reply format.

All of the above are pure file I/O with no LLM call inside them — the only tokens spent are on
the reaction/analysis text itself.

Reading manuscripts (novelWriter projects or flat `.md` files) is delegated to the
`manuscript-editor` skill's `nw_tool.py` — this skill only ever reads, never writes back to a
manuscript.

## Install

Requires [Python 3](https://www.python.org/) and the
[manuscript-editor](https://github.com/SwaroopShenoy/manuscript-editor-skill) skill installed
alongside it (for manuscript reading).

```
git clone https://github.com/SwaroopShenoy/beta-reader-panel-skill "%USERPROFILE%\.claude\skills\beta-reader-panel"
```

Claude Code auto-discovers skills under `~/.claude/skills/` — no further setup needed.

## Usage

> "Review chapter 3 of \<project\>" — analyst mode, the default. Ready by the 2nd message: the
> first reply asks only which manuscript (skipped if already obvious from context), then that
> chapter's full analysis follows in the same turn, and every subsequent chapter continues the
> same `_story_analysis/living_reference.md` record — no subagent, no panel roll, full book
> history available for callbacks.

> "Get the beta panel's reactions to chapter 3 of \<project\>" — panel mode, switched into
> explicitly whenever the ask is about reader reactions/opinions rather than a quality read.
> First run picks 2-3 random readers and locks them in for that manuscript. Each subsequent
> chapter, every panel member reacts independently, in character, based only on what they've
> "read" so far, logged to their own private file under
> `<manuscript>/_beta_reviews/<persona-slug>/living_reference.md`. Within one sitting, each
> persona's subagent is reused across chapters rather than respawned for every one (periodically
> refreshed to keep its own context bounded) — that reuse is what keeps a multi-chapter panel
> session cheap, on top of the file-based isolation.
